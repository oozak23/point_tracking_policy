Point-Memory Action Decoder

Since the go-ahead: the decoder is built and verified, six experiments have run on the full DROID set, and the results point to two separate problems — one of which needs a decision on the training objective.

Built & verified

Dataset, dataloader, replica block, readout, head, loss. Memorises 10 windows perfectly.

Measured

Proprioception halves the loss. Longer training doubles scene use, but not past the gate.

Needs your call

How to make the objective reward looking at the scene — residual target or action chunking.

Where things stand

  • The decoder learns. It fits 10 training windows to 1.03 mm and gets every gripper change right, so gradients reach through the full 71-frame recurrent rollout.

  • Proprioception is the biggest single gain. Adding the robot's own joint state halves validation loss and cuts spurious gripper changes from 1,889 to 136.

  • The model barely uses the scene. With proprioception, shuffling the object memory costs about 2% on every frame — including the hardest ones. Five epochs raised the visual model's scene effect to 8.7% — but uniformly, not at the frames where motion changes, and still short of the 10% gate.

  • It is still worse than repeating the last action — 7.65 mm against 4.55 mm. Part of that is training length; part is the objective.

The decoder

Your design: object points form a frozen scene memory; robot points feed a trainable replica of Track-On's block that keeps its own action memory and attends into the scene.

Experiments

In the order they ran. All numbers are on the same 63,598 held-out validation frames unless noted.

1 · overfitpassed

Can it learn at all?

Ten fixed windows, five labs. Passed at step 150: position 11.31 → 1.03 mm, rotation 1.67° → 0.195°, gripper changes 3/14 → 14/14. On the way it briefly learned "keep the gripper as it is" — accuracy rose while transitions got worse — then learned when to switch.

2 · one-epoch pilotall gates failed

Does it generalise?

Not yet: 9.99 mm against 4.55 mm for simply repeating the previous action. Validation was still falling when the budget ran out — the best checkpoint was the last one.

3 · train vs valunderfitting

Is it short of data?

No. Same checkpoint, dropout off: 10.03 mm on the training set, 9.99 mm on validation. It has not fitted what it already has, so more data would not help yet.

4 · + proprioceptionlarge gain

Is it missing an input?

Yes. The model only saw appearance tokens and had to infer its own motion from them. Feeding current joint positions, joint velocities and gripper width — one epoch, every other setting identical:

Every lab improved. The extra encoder is 70 k parameters on a 7.9 M model, far too small to explain halving the loss — this is the input, not capacity. But note the last row: with a direct signal of its own motion, the model uses the scene less.

5 · scene, by difficultyscene barely used

Does it use the scene where it matters?

The hypothesis was that the 2% was diluted: most frames are mid-motion, where "keep going" is right and no scene can help. So I split frames by how badly repeating the previous action does on them, and re-ran the same shuffle — reproducing the reported +2.14% exactly first. The effect is flat — and after five epochs it is flat again, just higher.

The same split shows where the gap to copy-last lives: the model is 4.3× worse on the easiest frames (3.47 vs 0.80 mm) and only 1.2× worse on the hardest. It has joint velocity and still cannot extrapolate steady motion precisely.

A caution about the five-epoch number. Shuffling the scene costs 9% even on steady-motion frames, where object positions should be irrelevant. One plausible reason: points on a grasped object move with the gripper, so the scene carries a second motion signal. If so, a rising scene-shuffle effect is not the same as the policy using object locations to decide. Testable by splitting on whether the gripper is closed.

6 · five epochshelps, slowing

Does training longer close the gap?

Visual only, five epochs. It helps, with diminishing returns — 8.49 mm at the end, the last epoch gaining only 0.19 mm — and one epoch with proprioception (7.65 mm) is still better than five without. Two things did move: gripper transition cost fell from 5.77 to 3.64 frames, and the scene-shuffle effect rose from 4.1% to 8.7%. Split by difficulty (experiment 5's chart), that rise is uniform: longer training raised scene use everywhere without concentrating it where the motion changes.

Diagnosis: two separate problems

Predicting 0.14 s ahead is mostly momentum. The objective rewards extrapolating the robot's own motion and gives little gradient toward the scene, so under-using the objects is a rational response to what the model is asked. Wen et al. (2020) call this the copycat problem in behaviour cloning. Training longer eases it; proprioception — which the model clearly needs — makes it worse.

Imprecise momentum 4.3×

worse than copy-last on steady-motion frames. The model must learn the arm's joint-to-gripper mapping from joint velocities. More training helps; giving it momentum directly would help more.

Scene under-used 2.1% · 8.7%

scene-shuffle effect: with proprioception after one epoch, and visual-only after five. Both are flat across difficulty — training raises scene use everywhere but does not teach the model when it matters. The objective is still the lever.

Decisions for you

  1. A

    What should the next objective reward?

    Residual target — predict the next action minus the previous one. Copy-last becomes the zero point, so momentum comes free and only the non-momentum part is left to learn. One-line change, one epoch to test.

    Action chunking — predict the next 16 steps (~2 s). Over that horizon momentum cannot explain the motion, so the model has to anticipate — which needs the scene. ACT's core idea and DECISIONS.md §3. Needs a dataloader extension and a new causality test.

    Suggested: run the residual target now; build chunking in parallel.

  2. B

    If chunking: which loss?

    At 0.14 s there is almost no ambiguity. At 2 s, trajectories branch — left or right of the bowl — and plain MSE averages the branches into a path nobody took: the regression-to-the-mean failure we diagnosed in PointWorld. ACT pairs chunking with a CVAE for exactly this; Behavior Transformers use a whole-action classifier plus residual.

    Suggested: MSE first as the baseline; switch if predicted chunks fall between demonstrated paths.

  3. C

    Gripper target: observed state or recorded command?

    We train on the next observed gripper state. DROID also records the operator's actual command (action/gripper_position), which leads the physical state through the controller — the cleaner signal for learning when to grasp.

  4. D

    For your awareness — already adopted

    Clips with tracking error above 50 px are dropped (1.4%) and the rest are weighted by tracking quality instead of cut, so no lab is disproportionately removed. 32,031 further PointWorld episodes exist outside this set; they are not needed until the model stops underfitting.

Next

The new baseline should be proprioception trained for five epochs, since each helps independently. Then, depending on A: the residual target, and chunking built and verified alongside it. Every run is judged against copy-last on held-out episodes, per lab, with the scene-shuffle split by difficulty and by whether the gripper is closed. The proprioception five-epoch run is already training.
